# BD-Planner 사용법 (Windows, Python 3.9+, 추가 설치 없음)

```
python bd_planner.py new 사진2차 "H:\사진 2차 백업"          # 원본 폴더는 직접 지정 (--capacity-gb 90, --binary 로 GiB)
python bd_planner.py subfolders 사진2차                       # 하부 폴더 목록 확인
python bd_planner.py select 사진2차 폴더A 폴더B 폴더C         # 백업 대상, 적은 순서가 배정 순서
python bd_planner.py scan 사진2차                             # 스캔(읽기 전용) + 90G 배정 + 선경고 + 예상 디스크 수
python bd_planner.py show 사진2차                             # disk01.. 배정 결과, 분할 폴더 표시
python bd_planner.py capacity 사진2차 1=95 2=23.3 3=45        # 디스크별 용량 지정(기본 용량과 다르게). --binary 로 GiB
python bd_planner.py capacity 사진2차 2=default               # 한 디스크만 기본 용량으로 / --clear 는 전체 해제
python bd_planner.py allocate 사진2차                         # 재스캔 없이 현재 용량 설정으로 다시 배정
python bd_planner.py export 사진2차 --stage "H:\_BD_STAGE" --disks 1   # 하드링크 스테이징 + INDEX.txt + CSV
python bd_planner.py status 사진2차 1 완료                    # 계획됨/굽는 중/완료/검증됨
python bd_planner.py verify 사진2차 1 "F:\"                   # 경로·크기를 DB 와 대조(내용 비교 아님, 상태는 안 바꿈)
```
ImgBurn: Build 모드 → 소스에 `H:\_BD_STAGE\disk01` 폴더 추가(폴더 내용이 디스크 루트가 되도록
"Add Folder"가 아닌 폴더 내용 추가 사용) → 파일시스템 UDF → 볼륨 라벨은 INDEX.txt 첫 줄 참고 → 굽기.
스테이징은 원본과 같은 NTFS 드라이브여야 합니다. 굽기 후 스테이징 폴더를 지워도 원본은 안전합니다.

## GUI
```
python bd_planner_gui.py
```
(Windows 정식 Python에는 tkinter 포함. 같은 폴더의 bd_planner.py, DB는 bd_planner.db 사용 — CLI와 공유)
순서: ① 원본 폴더 [찾아보기] + 계획 이름 + 용량 → [폴더 목록 읽기] → ② ☑ 선택·▲▼ 순서 → ③ [스캔 + 배정 계산]
→ ④ 디스크 선택 후 상태 변경/검증 → ⑤ 스테이징 위치 지정 후 [선택 디스크 내보내기] → ImgBurn.

## 디스크별 용량 직접 지정 (CLI 전용)
디스크마다 다른 크기를 쓸 수 있습니다(예: disk01=BDXL 95GB, disk02=25GB 디스크 23.3GB 등).
- 지정하지 않은 디스크는 계획의 **기본 용량**을 씁니다. disk01부터 순서대로 채우므로 앞 디스크의 구성은 뒤쪽 용량을 바꿔도 그대로입니다.
- GUI 에서는 이 항목을 뺐습니다. 디스크별 크기는 아래 **미디어 종류(100G/50G/25G)** 선택으로 지정하세요.
  예전에 CLI 로 직접 지정한 용량이 있으면 표의 용량 열에 `*` 로 보이고, **해제**(또는 다른 미디어 지정)로 지워집니다.
- 이미 구운 디스크(`완료`/`검증됨`)는 재배정해도 구성이 같으면 상태를 유지하고, 구성이 바뀌면 `계획됨`으로 초기화하며 경고를 표시합니다.
- 어느 디스크에도 들어가지 않는 큰 파일은 배정에서 제외(경고), 용량이 너무 작아 비게 된 디스크는 경고합니다.
- INDEX.txt 에 해당 디스크의 용량 기준이 함께 기록됩니다.

## 나중에 새 하위 폴더가 생겼을 때 (증분 추가)
**구운 디스크가 있으면 같은 계획을 `scan`(전체 재스캔)하지 마세요.** 모든 배정·디스크 상태가 초기화됩니다
(CLI 는 `--force` 없이는 거부, GUI 는 경고 확인). 대신:
```
python bd_planner.py add 사진2차 --list        # 원본에 새로 생긴 하위 폴더 확인
python bd_planner.py add 사진2차               # 새 폴더 전부 추가(폴더명을 적으면 그것만)
python bd_planner.py export 사진2차 --stage "H:\_BD_STAGE" --disks 7 8   # 출력에 표시된 '바뀐 디스크'만
```
- 새 폴더만 읽어 선택 목록 끝에 붙입니다. 기존 파일 목록과 **구운 디스크('계획됨'이 아닌 것)는 변경하지 않습니다.**
- '계획됨' 디스크의 남는 공간을 번호순으로 먼저 채우고, 넘치면 새 디스크(마지막 번호+1…)를 만듭니다(디스크별 용량 반영).
- GUI: [폴더 목록 읽기] → 새 폴더에 '신규' 표시 → ☑ 체크 → **③' 새 폴더만 추가 배정**.
- 기존 폴더 '안'에 파일이 추가·삭제·변경된 경우는 감지하지 않습니다(새 하위 폴더 추가만 지원).

## 백업 이력 관리
디스크마다 '언제 무엇을 했는지'가 DB 에 쌓입니다(전체 재스캔을 해도 이력은 유지).
```
python bd_planner.py record 사진2차 1 --media "VERBAT-IMk-000 #1" --location "책장 A"   # 백업 완료 기록(사본 #1)
python bd_planner.py record 사진2차 1 --media "VERBAT-IMk-000 #2" --location "은행 금고"  # 같은 디스크의 사본 #2
python bd_planner.py history 사진2차 [--disk 1]                                          # 사본 기록 + 이력
```
- 자동 기록되는 이벤트: 스테이징 내보냄, 상태 변경, 추가 배정, 구성 변경으로 상태 초기화, 전체 재스캔, 미디어 비교 결과.
- 사본(복사본)별로 미디어 ID·보관 위치·구운 시각·마지막 검증 결과를 관리합니다.
- GUI: 디스크를 선택하고 **백업 완료 기록…** / **이력 보기…**. 디스크 표에 `사본` 수와 `최근 검증`이 표시됩니다.

## 스테이징(원본) ↔ 미디어 일치 검사
```
python bd_planner.py compare 사진2차 1 --stage "H:\_BD_STAGE" --media "I:\"          # 전체(바이트) 비교
python bd_planner.py compare 사진2차 1 --stage "H:\_BD_STAGE" --media "I:\" --quick  # 존재·크기만
```
- 스테이징 `diskNN` 폴더와 미디어를 파일별로 대조합니다. **전체 비교**는 모든 파일을 바이트 단위로 읽어 비교하므로
  95GB 디스크는 오래 걸리지만, 내용 변조·읽기 불량까지 잡습니다. **빠른 검사**는 없는 파일·추가 파일·크기 차이만 봅니다.
- **전체 비교가 모두 일치해야 상태가 '검증됨'**이 됩니다. 불일치가 나오고 일치한 다른 사본이 없으면 '검증됨'→'완료'로 되돌립니다.
- 숨김/시스템 속성 파일(Picasa.ini, Thumbs.db 등)은 ImgBurn 이 기본으로 굽지 않으므로 미디어에 없어도 실패로 치지 않고
  "숨김/시스템 파일 미포함"으로 따로 보고합니다.
- 종료 코드: 일치 0, 불일치 1 (스크립트 연동용). GUI: **스테이징↔미디어 비교…**(스테이징 위치는 ⑤에서 지정).
- 스테이징이 사라졌다면(굽고 지움) 비교할 수 없습니다. 검증이 끝날 때까지 스테이징 폴더를 지우지 마세요.

## 미디어 종류(100G / 50G / 25G)와 오버헤드
미디어 종류마다 **기록 가능 용량**과 **오버헤드**를 따로 갖고, 디스크별로 종류를 골라 그 값으로 배정합니다.

| 키 | 이름 | 기본 용량(바이트) |
|---|---|---|
| BD100 | BD-R XL 100GB | 100,103,356,416 |
| BD50 | BD-R DL 50GB | 50,050,629,632 |
| BD25 | BD-R 25GB | 25,025,314,816 |

- 용량은 드라이브가 보고하는 Free Space(섹터 × 2048)입니다. ImgBurn Device 탭의 값과 같습니다.
- 오버헤드는 두 가지: **파일당**(기본 4096바이트, 파일마다 더함) · **디스크당 고정**(기본 64MiB, 디스크 용량에서 미리 뺌).
  실제 ImgBurn 이미지는 파일 크기 합보다 조금 크므로(UDF 메타데이터·섹터 올림) 이 값으로 보정합니다.
- 사용 가능 용량 = 미디어 용량 − 고정 오버헤드. 종류 설정은 모든 계획에 공통입니다.
```
python bd_planner.py mediatypes                                     # 세 종류의 값 보기
python bd_planner.py mediatypes --set BD100 --per-file 4096 --fixed-mb 64   # 값 수정(--capacity-gb, --label 도 가능)
python bd_planner.py mediatypes --reset                             # 기본값 복원
python bd_planner.py media 사진2차 BD100 --default                  # 지정 없는 디스크의 기본 미디어
python bd_planner.py media 사진2차 BD50 --disks 3 4                 # 디스크별 지정
python bd_planner.py media 사진2차 BD25 --from 6                    # 6번부터 현재 마지막 디스크까지
python bd_planner.py media 사진2차 --clear --disks 3                # 지정 해제(--disks 생략 시 전체)
python bd_planner.py allocate 사진2차                               # 지정을 반영해 재배정
```
- 우선순위(용량): 디스크별 직접 지정 용량 > 디스크에 지정한 미디어 > 기본 미디어 > 계획의 '디스크 용량' 숫자.
  오버헤드(파일당)는 지정/기본 미디어의 값, 없으면 계획의 숫자. 미디어를 고르면 그 디스크의 직접 지정 용량은 지워집니다.
- GUI: ① 설정의 **기본 미디어** 콤보와 **미디어 종류 설정…**(용량·오버헤드 수정), ④ 결과에서 디스크를 선택하고
  **선택 디스크 미디어**를 골라 **적용 후 재배정** / **선택 번호~끝까지** / **해제**. 표의 `미디어`·`용량` 열이 디스크별 값을 보여 줍니다.
- 이미 구운 디스크는 재배정 후 구성이 같으면 상태가 유지됩니다(기존 규칙). 오버헤드·용량을 바꾸면 구성이 달라질 수 있으니
  구운 디스크가 있으면 값을 바꾸기 전에 확인하세요.

## 설정 저장 / 불러오기 (①~⑤)
화면 설정을 JSON 파일로 저장해 두고 다시 불러옵니다(다른 PC로 옮길 때도 사용).
- 저장 내용: 원본 폴더·계획 이름·디스크 용량(단위)·파일당 오버헤드, 기본 미디어, **백업 대상 폴더의 선택과 순서**,
  **디스크별 미디어 지정**, 100G/50G/25G 용량·오버헤드 값, 스테이징 위치. (스캔 결과·배정·이력은 저장하지 않음 — DB 에 있음)
- GUI: ① 설정의 **설정 저장…** / **설정 불러오기…**. 불러오면 계획을 만들거나 갱신하고, 목록의 ☑·순서를 복원합니다.
  미디어 지정은 DB 에만 반영되므로 배정에 쓰려면 **재배정**을 누르세요.
- 이 PC에 원본 폴더가 없으면 새 폴더를 고르라고 묻습니다. 100G/50G/25G 값이 현재와 다르면 적용 여부를 묻습니다(공통 값).
- 스캔 결과가 있는 계획에 불러오면 DB 의 폴더 선택은 바꾸지 않고(화면 선택만 복원), 원본 폴더가 다르면 초기화 여부를 묻습니다.
- 프로그램을 닫을 때 마지막 ① 화면 값을 `bd_planner_gui_state.json` 에 자동 저장하고, 다음 실행 때 복원해 폴더 목록을 읽습니다.
```
python bd_planner.py save-settings 사진2차 설정.json --stage "H:\_BD_STAGE"
python bd_planner.py load-settings 설정.json --root "D:\사진 2차 백업"      # --name 새이름, --apply-media-types, --force
```

## 복사 후 비교 (미디어 → 임시 위치 → 스테이징)
미디어와 스테이징을 직접 맞대 비교하는 대신, **미디어의 파일을 먼저 하드디스크의 임시 위치로 복사하고 그 복사본을 스테이징과 비교**합니다.
- 설정(⑤ 출력): **스테이징 위치**와 **임시 복사 위치**를 지정합니다. 임시 복사 위치는 설정 저장/불러오기와 마지막 화면 값 복원에도 포함됩니다.
  **일치하면 임시 복사본 삭제**(기본 켜짐)를 끄면 항상 남깁니다. 불일치나 복사 실패가 있으면 복사본은 항상 보존합니다.
- GUI: 디스크를 선택하고 **복사 후 비교…** → 미디어 드라이브 선택. 복사 중 읽기 실패는 파일별로 기록하고 계속 진행하며,
  끝나면 복사본을 스테이징과 **전체(바이트) 비교**합니다. 전체 일치해야 `검증됨`이 됩니다. 디스크를 한 번만 읽고, 읽기 실패한 파일 이름이 정확히 나옵니다.
```
python bd_planner.py compare 사진2차 9 --stage "H:\스테이징" --media "I:\" --via-copy "E:\"           # 복사 후 비교
python bd_planner.py compare 사진2차 9 --stage "H:\스테이징" --media "I:\" --via-copy "E:\" --keep-copy  # 일치해도 복사본 보존
```
- 임시 폴더는 `<임시 위치>\_bd_verify\<계획>_diskNN` 입니다. **이 프로그램이 만든 표식 파일이 있는 폴더만 지우며**,
  이미 있는 다른 폴더는 지우지 않고 중단합니다. 임시 위치가 스테이징·미디어와 겹치면 거부합니다. 여유 공간이 미디어 크기보다 작으면 시작 전에 중단합니다.
- 시간은 `디스크 읽기(복사) + 복사본·스테이징 읽기(비교)` 의 합이라 직접 비교보다 오래 걸릴 수 있습니다. 대신 불량 파일을 정확히 찾고,
  읽히는 파일은 복사본으로 건질 수 있으며(보존 시), 비교를 다시 해도 디스크를 또 읽지 않습니다.
- 검증 결과는 이력에 `미디어 비교(복사 경유)`로 기록됩니다.

## 비교 진행 표시
미디어 비교·복사 후 비교 중에는 화면 하단 상태 표시줄에 **현재 파일명, 처리 건수, 읽은 용량**이 표시되고, 오른쪽에 **전체 진행률 막대와 퍼센트**가 표시됩니다.
- 전체(바이트) 비교는 읽은 바이트 기준, 빠른 검사는 파일 수 기준 진행률입니다.
- 복사 후 비교는 `[1/2 복사]` → `[2/2 비교]` 단계가 표시되고 진행률은 두 단계를 합쳐 0~100%입니다(복사 50% + 비교 50%).
- 긴 경로는 가운데를 `…`로 줄여 표시합니다. CLI(`compare`)도 같은 정보를 한 줄로 표시합니다.

## 스테이징 → ISO (UDF 2.50, ImgBurn 없이) — 검증 먼저
스테이징 폴더(`diskNN`)를 **파일 시스템 UDF, 리비전 2.50, UDF 라벨 지정**으로 ISO 파일로 만듭니다. **바로 만들지 않고 사전 검증부터** 합니다.
```
python bd_planner.py make-iso 사진2차 9 --stage "H:\스테이징" --iso "E:\disk09.iso" --check-only   # 검증만(아무것도 쓰지 않음)
python bd_planner.py make-iso 사진2차 9 --stage "H:\스테이징" --iso "E:\disk09.iso" --label disk09  # 검증 → 확인(y) → 생성 → 생성물 검증
python bd_planner.py inspect-iso "E:\disk09.iso" --label disk09                                       # 이미 있는 ISO 의 라벨·리비전·파일 시스템 확인
```
- **① 사전 검증(쓰기 없음)**: 디스크 배정 존재 · 스테이징 폴더 · **스테이징 = 배정(경로·크기)** · **미디어 용량**(예상 이미지 ≤ 미디어) · 경로 길이(260자) ·
  **UDF 볼륨 라벨 규칙** · 저장 폴더/기존 파일/여유 공간/스테이징 안에 저장 금지 · **IMAPI 가 UDF 2.50 을 지원하는지**(지원 목록에 없으면 중단).
  하나라도 실패하면 ISO 를 만들지 않습니다. 결과는 이력에 남습니다.
- **② 확인** → **③ 생성**(Windows 내장 IMAPI2 로 UDF 전용, 리비전 2.50, 라벨 지정) → **④ 생성물 검증**: ISO 파일을 직접 읽어
  *UDF 인지 · ISO9660 구조가 섞이지 않았는지 · 리비전 2.50 · 라벨 · 크기* 를 확인합니다. 통과하지 못하면 "이 ISO 로 굽지 마세요"로 알립니다.
- 라벨 규칙: 영문·숫자 31자, 한글처럼 16비트 문자가 있으면 15자까지(UDF 볼륨 식별자 32바이트 제한). 기본 라벨은 `diskNN`.
- GUI: ⑤ 출력의 **ISO 저장 위치** 지정 → 디스크 선택 → **ISO 만들기 (검증 먼저)…** → 검증 결과를 보고 확인해야 생성됩니다. 저장 위치는 설정에 포함됩니다.
- **Windows 전용**(PowerShell + IMAPI2). 다른 OS 에서는 사전 검증까지만 되고 생성은 거부합니다. 굽기는 이 기능의 범위가 아니며 ImgBurn Write 모드로 이 ISO 를 굽습니다.
- 알려진 한계(아직 실제 Windows 에서 확인되지 않음): IMAPI 가 2.50 을 지원하는지는 실행 시 확인하며, ISO 안의 리비전 필드는 값이 여러 곳에 있어
  (도메인/최소읽기/최소쓰기/최대쓰기) 그중 하나라도 2.50 이면 통과로 봅니다. 260자 넘는 경로, 숨김·시스템 파일의 포함 여부는 ImgBurn 과 다를 수 있으니
  **처음에는 작은 디스크 하나로 시험**하고 `inspect-iso` 와 ImgBurn Verify 로 확인하세요.

## 진행 표시: 전체 진행률 · 경과 시간 · 남은 시간 (모든 작업 공통)
오래 걸리는 작업(ISO 생성, 미디어 비교, 복사 후 비교, 스테이징 내보내기, 스캔 등)은 하단 표시줄에 같은 형식으로 보입니다.

`ISO 생성 중… 37.4% · 31.2 GB / 83.4 GB  ·  경과 12:08  ·  남은 약 20:15`  (오른쪽에 진행 막대와 퍼센트)

- **전체 진행률**: 총량을 아는 작업은 퍼센트와 막대. 복사 후 비교는 복사+비교를, 내보내기는 선택한 모든 디스크를 합친 0~100%입니다.
- **경과 시간**: 1초마다 갱신됩니다(진행 메시지가 뜸해도 시간은 계속 흐름). 작업이 끝나면 로그에 `⏱ … 총 mm:ss 소요`가 남습니다(3초 이상일 때).
- **남은 시간**: 최근 45초의 속도와 전체 평균 속도를 섞어 추정합니다(최근 70%). 처음 3초·0.5% 전에는 `계산 중…`입니다.
  속도가 크게 바뀌는 작업(디스크 읽기 오류로 느려지는 구간 등)에서는 값이 흔들리거나 낙관적일 수 있습니다.
- **총량을 모르는 작업**(스캔·새 폴더 추가 스캔): 건수·용량·경과 시간만 표시하고 막대는 움직이는 표시로 바뀝니다. 남은 시간은 표시하지 않습니다.
- CLI(`compare`, `make-iso`, `export`, `scan`, `add`)도 한 줄에 같은 정보(단계·%·건수·용량·경과·남은 시간·파일명)를 표시합니다.

**새 기능을 추가할 때(개발 메모)**: GUI 작업은 `run_bg` 로 실행하면 경과 시간이 자동으로 표시되고, 진행 중에
`self.q.put(("prog", None, "문구"))` 와 `self.q.put(("pct", None, 퍼센트))` 만 보내면 진행 막대·남은 시간이 같은 방식으로 켜집니다.
핵심 함수는 `progress(info)` 콜백(`phase`, `file`, `files_done/total`, `bytes_done/total`, `percent`)을 받는 형태로 만들고,
CLI 는 `cli_progress("라벨")`, 시간 계산은 `Eta` 클래스, 표기는 `fmt_duration` 을 쓰면 됩니다.
